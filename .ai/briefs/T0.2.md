## `ds.config.json` — exactly this content

```json
{
  "name": "ds",
  "scope": "@ds",
  "tokenPrefix": "ds",
  "dataPrefix": "ds",
  "dsContracts": {
    "enabled": false,
    "schema": "16.0.0",
    "cli": "0.4.0",
    "outDir": ".ai/ds-contracts"
  }
}
```

## `scripts/lib/config.ts`

- Export `DsConfigSchema` (Zod, `z.strictObject` at both levels so unknown keys are refused).
- Rules:
  - `name`, `tokenPrefix`, `dataPrefix`: lowercase kebab-case, `^[a-z][a-z0-9-]*$`
  - `scope`: `@` followed by the same pattern
  - `dsContracts.enabled`: boolean
  - `dsContracts.schema`, `dsContracts.cli`: exact semver, `^\d+\.\d+\.\d+(-[0-9A-Za-z.-]+)?$` (no ranges)
  - `dsContracts.outDir`: a relative path under `.ai/` (must start with `.ai/`, must not contain `..`)
- Export `type DsConfig = z.infer<typeof DsConfigSchema>`.
- Export `class ConfigError extends Error`.
- Export `loadConfig(path?: string): DsConfig`. Default path: `ds.config.json` at the repository root,
  resolved from this file's location (not `process.cwd()`), so it works from any directory.
  - Missing file → `ConfigError` saying the file is missing and where it was expected.
  - Invalid JSON → `ConfigError` naming the file.
  - Schema failure → `ConfigError` listing **every** problem, one per line, each as
    `<dotted.field.path>: <reason>` (e.g. `dsContracts.schema: must be an exact version like 16.0.0`).
- Synchronous (`readFileSync`). No other dependencies.
